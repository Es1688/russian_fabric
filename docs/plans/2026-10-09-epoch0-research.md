## 1. Загрузка файлов в MAX Bot API (POST /uploads)

**Кратко:** платформа принимает медиа по двухшаговой схеме «получить URL → загрузить
файл → прикрепить токен к сообщению». В текущем `MaxClient` этого нет, но фундамент
(base_url, авторизация, типизированные ошибки) уже готов — нужен точечный набор
доработок.

### 1.1 Как работает загрузка

1. **Запрос URL загрузки**: `POST https://platform-api2.max.ru/uploads?type={type}`
   (использовать именно `platform-api2.max.ru`). Авторизация — заголовок
   `Authorization: {access_token}` с сырым токеном, без `Bearer`; авторизация
   query-параметрами больше не поддерживается ни в одном методе. Это ровно та же схема,
   что уже реализована в `max_news_bot/max_api/client.py:123`.
   Ответ 200 — JSON с URL для загрузки вложения (и токеном для части типов).
   Источник: [dev.max.ru/docs-api/methods/POST/uploads](https://dev.max.ru/docs-api/methods/POST/uploads)
2. **Загрузка файла**: отдельный `POST` на полученный URL — это CDN-хосты вида
   `iu.oneme.ru` / `*.okcdn.ru`, не platform-api. Тело — `multipart/form-data` с
   единственным полем `data`, значением которого является загружаемый файл. Для video
   есть альтернативный resumable-вариант (частями, не multipart).
   Источник: [sending-messages/media](https://dev.max.ru/docs-api/use-cases/sending-messages/media)
3. **Отправка сообщения с вложением**: токен прикрепляется через `POST /messages`
   (или `PUT /messages` при редактировании) в теле:
   `{"attachments": [{"type": "image|video|audio|file", "payload": {"token": "<mediafile_token>"}}]}`.
   Для image допустима также загрузка по прямой ссылке `payload.url`.

### 1.2 Типы и лимиты

`type` — enum `image | video | audio | file`; значение `photo` из старых версий больше
не поддерживается.

| Тип | Форматы | Лимит размера | Прочее |
|---|---|---|---|
| image | JPG/JPEG/PNG/GIF/TIFF/BMP/HEIC | до 50 МБ **и** до 7680×7680 px (оба условия) | до 12 видео+изображений в одном сообщении |
| video | MP4/MOV/MKV/WEBM | до 250 МБ | |
| audio | MP3/WAV/M4A и др. | до 256 МБ и 60 мин | |
| file | TXT/DOC/PDF и др. | до 4 ГБ | не более одного, не сочетается с изображениями/видео |

Неподдерживаемое расширение → ошибка `File extension is forbidden`. Общий лимит
платформы `platform-api2.max.ru` — 30 запросов/сек.
Источник: [sending-messages/media](https://dev.max.ru/docs-api/use-cases/sending-messages/media)

### 1.3 Где брать токен вложения (ключевой нюанс)

Формат ответа зависит от типа — документация противоречива (страница метода описывает
ответ 200 как «URL + токен» для всех, use-case уточняет):

- **audio/video**: токен приходит уже в ответе `POST /uploads` (`{"url": ..., "token": ...}`);
  сама загрузка файла отвечает 200 без тела;
- **image**: в ответе `/uploads` только `url`; токен появляется **после** загрузки файла
  в виде `{"photos": {"photoIds": {"token": "<mediafile_token>"}}}`;
- **file**: после загрузки — `{"fileId": ..., "token": "<mediafile_token>"}`.

Надёжная стратегия — искать токен в обоих местах (`token` | `photos.photoIds.token`).

### 1.4 Асинхронная обработка

После загрузки файл обрабатывается сервером асинхронно: отправка сообщения сразу может
упасть с ошибкой `attachment.not.ready` (`errors.process.attachment.file.not.processed`).
Документация рекомендует паузу и повторные попытки с возрастающим интервалом; в
обновлениях чата приходит `attachment.status` (2 — processing, 0 — ready).

### 1.5 Что добавить в `max_news_bot/max_api/client.py`

Текущее состояние (по коду, прочитанному в исследовании): `base_url` уже
`https://platform-api2.max.ru` (`client.py:16`); `_request` умеет только query-params и
JSON-тело (`client.py:108-138`); `send_message` шлёт `{text, format, notify}` без
attachments (`client.py:43-63`). Типизированные ошибки `MaxApiError / MaxRateLimitError /
MaxBadResponseError` уже покрывают ответы `/uploads` (400/401/429/500 и не-JSON тело,
`client.py:214-228`) — новых классов ошибок не требуется.

Доработки:

1. `MaxClient.get_upload_url(upload_type: str) -> dict` — `POST /uploads` с
   `params={'type': upload_type}`, парсинг существующим `_parse_object`;
2. `MaxClient.upload_media(upload_url, data: bytes, filename, content_type, *, send_auth=False)`
   — POST multipart/form-data с полем `data` на **полный внешний CDN-URL**; требует
   расширить `_request`/`_send` параметром `form: aiohttp.FormData | None` и опцией не
   подставлять `Authorization` (примеры документации для audio/video/file не включают
   этот заголовок на CDN-хостах; только пример image его содержит — потому `send_auth`
   как флаг). Ответ может быть пустым (audio: 200 без тела) → возвращать `{}`;
3. хелпер `_extract_upload_token(data: dict, upload_type: str) -> str` — токен из
   `data['token']` либо `data['photos']['photoIds']['token']`; отсутствующий токен —
   `MaxBadResponseError`;
4. расширить `send_message(..., attachments: list[dict] | None = None)`, добавляя
   `attachments` в json_body (`client.py:61`);
5. ретраи с паузой и возрастающим интервалом на `attachment.not.ready`, пока сервер
   не обработает файл.

## 2. YandexART (генерация изображений)

**Кратко:** генерация изображений доступна через **тот же OpenAI-совместимый endpoint
Yandex AI Studio**, который проект уже использует для текста. Отдельный асинхронный API
не нужен. Остаётся один live-вопрос — схема авторизации (Bearer vs Api-Key).

### 2.1 Доступность

- Текущий endpoint проекта: `POST {base_url}/chat/completions`, base_url по умолчанию
  `https://ai.api.cloud.yandex.net/v1`, модель `gpt://FOLDER_ID/yandexgpt-5-lite`
  (`max_news_bot/writers/llm.py:56,162,165`; `max_news_bot/config/loader.py:157-167`).
- Images API (генерация изображений) входит в состав тех же OpenAI-совместимых API
  AI Studio: синхронный `POST https://ai.api.cloud.yandex.net/v1/images/generations`.
  Официальная страница:
  [Как сгенерировать изображение с помощью OpenAI-совместимого API](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/images-generation).
- Живая проба из исследования (curl без ключа): `model="yandex-art"` → HTTP 400
  `Failed to parse model URI`; `model="art://b1g0000000000000/yandex-art/latest"` →
  HTTP 401 «IAM token or API key has to be passed» — endpoint существует и валидирует
  модель до авторизации, формат `art://<folder>/<model>` принимается.

### 2.2 Формат запроса и ответа

- Запрос: `{"model": "art://<folder_id>/aliceai-image-art-3.0", "prompt": "...",
  "size": "1024x1024"}`; из параметров OpenAI Images API поддерживается `size`;
  максимальная длина промпта — 500 символов; режим синхронный.
- Ответ: изображение — base64-строка в `data[0].b64_json` (декодировать в PNG/JPEG);
  URL-режим не заявлен.
- Актуальная модель в таблице «Доступные генеративные модели» — **Alice AI ART**
  (`art://<folder_id>/aliceai-image-art-3.0`); классического YandexART под именем
  `yandex-art` в таблице больше нет — считать legacy и проверять на живом ключе
  (официальный SDK его ещё использует:
  [пример в yandex-ai-studio-sdk](https://github.com/yandex-cloud/yandex-ai-studio-sdk/blob/master/src/yandex_ai_studio_sdk/_models/image_generation/function.py)).

### 2.3 Авторизация (⚠ открытый вопрос)

В официальных примерах для Images API — заголовки `Authorization: Api-Key <ключ>` и
`OpenAI-Project: <folder_id>`. Текущий `LlmWriter` шлёт `Bearer` (для Chat Completions
это работает). Принимает ли `/v1/images/generations` Bearer — не проверено (нет ключа
в окружении исследования); если нет — добавить пару `Api-Key` / `OpenAI-Project`.

### 2.4 Стоимость и лимиты

- **Стоимость**: 0,0182786856 $ без НДС (**2,23 ₽ вкл. НДС** / 11,15 ₸) за один запрос
  генерации; тарификация за каждый запрос, запросы **не идемпотентны** — повтор
  оплачивается отдельно. Для сравнения: YandexGPT Lite 5 — 0,60 ₽ / 1000 токенов.
  Источник: [pricing](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing).
- **Квоты**: 500 генераций/мин, 5 000/день, 50 запросов результата/сек, промпт
  ≤ 500 символов, хранение сгенерированных изображений — 12 часов.
  Источник: [Квоты и лимиты](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/limits).
  Для дайджест-пайплайна (единицы картинок в сутки) — запас на порядки.

Существует и отдельный нативный асинхронный API
(`foundationModels/v1/imageGenerationAsync`, поллинг Operation; подтверждён документацией,
живой пробой 401 и [официальным protobuf](https://github.com/yandex-cloud/cloudapi/blob/master/yandex/cloud/ai/foundation_models/v1/image_generation/image_generation_service.proto)) —
для проекта он **не нужен**, синхронного Images API достаточно.

## 4. Риски и открытые вопросы

**MAX uploads**

- Живой вызов API не выполнялся: прямой доступ из среды исследования к `dev.max.ru` и
  `platform-api2.max.ru` обрывался на TLS-рукопожатии; все факты — из официальной
  документации, прочитанной через прокси-ридер. Не проверено на живом токене: точный
  HTTP-статус ошибки `attachment.not.ready` (ожидается 400 с code в теле), поведение при
  превышении лимитов размера/разрешения, фактическое время жизни ссылки (страница метода
  заявляет «не ограничен», но URL в примерах содержат `sig` и `expires`).
- Документация внутренне противоречива по месту появления токена (см. §1.3) — поэтому
  предложено парсить оба места.
- Семантика multipart-поля `data` (содержимое файла как file-part) подтверждена сторонней
  практикой ([LiveHelperChat](https://github.com/LiveHelperChat/livehelperchat/issues/2355)),
  а не официальной докой; типовые страницы `/docs-api/types/*` (например Attachment)
  возвращают 404 — схема восстановлена по use-case.

**YandexART**

- Реальная генерация не запускалась (нет API-ключа, секреты не читаются). Проверки —
  только HTTP-пробы без авторизации (400/401), подтверждающие существование endpoint'ов.
- Открытые live-вопросы: принимает ли `/v1/images/generations` текущий `Bearer`-ключ или
  нужна пара `Api-Key` + `OpenAI-Project`; работает ли legacy-имя `yandex-art/latest`.
- Квоты 500/мин и 5 000/день — базовые значения; индивидуальные квоты каталога могут
  отличаться. Internet Archive в момент исследования был офлайн — исторические версии
  страниц цен/лимитов не проверены, цифры взяты с текущих живых страниц.

**RSS**

- Ленты проверены на момент 2026-10-09; формат и доступность со временем меняются
  (примеры: РИА и ТАСС уже закрыли тематические RSS) — нужен мониторинг «молчания»
  источников из плана (§14 «риски»).
- Остаточный риск контента (военные лонгриды в «Культуре»/«Науке» Газеты, поражения в
  спорте, викторины «Вокруг света») рассчитан на цепочку фильтров §5 п.1–5 и на
  тестовой неделе §13 подтверждается на живых данных.

**Open-вопросы, требующие live-теста с токенами (этап внедрения):**

1. `POST /uploads` + загрузка в CDN + отправка attachments с реальным токеном бота;
   зафиксировать фактический статус/код `attachment.not.ready`.
2. `POST /v1/images/generations` с реальным ключом: схема авторизации, имя модели
   (`aliceai-image-art-3.0` vs `yandex-art/latest`), качество картинок под стиль §12.

## 5. Что подтвердить оператору

### 5.1 Режим картинок: `bank` | `yandexart`

План §12: основа — банк заранее подготовленных открыток в едином стиле; генерация
YandexART — как дополнение, «если проверка подтвердит качество и стабильность».
Проверка этапа 0 показала: YandexART технически доступен через текущий endpoint,
~2,23 ₽ за картинку, лимиты с запасом; но качество/авторизация подтверждены только
live-тестом (§4). Варианты решения:

- **`bank`** — только банк открыток; LLM-генерация картинок не используется, стоимость 0 ₽;
- **`yandexart`** — генерация всех картинок через YandexART (~2,23 ₽/шт., при 2 картинках
  в сутки по сетке §2 — ~135 ₽/мес);
- **`bank` + `yandexart` как опция** (рекомендация исследований) — банк как основа и
  деградация, YandexART включается флагом после успешного live-теста на этапе внедрения.
